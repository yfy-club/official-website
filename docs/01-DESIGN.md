# 01 · 设计系统

> 云飞扬 · **Ink & Ember**（墨与烬）
> 所有对比度数值均已实测，标注格式：`色值 → 对比度:1`

---

## 1. 视觉主题与气质

深墨底色上的一点余烬。整站的主体是**近乎无彩的墨色与纸色**——90% 的像素是中性色，信息层级完全靠明度与留白建立，而不是靠颜色区分。唯一的彩色是一个偏暖的赤陶橙（Ember），它在一屏里最多出现两次。正因为稀有，它出现的地方就一定是重要的地方。

这套系统刻意站在"技术社团网站"的对立面：不用霓虹紫蓝渐变、不用发光卡片、不用赛博网格背景。取而代之的是**编辑设计的语汇**——高对比衬线大字、克制的分栏、表格就用表格、大面积留白。一个技术社团长得像一本设计年鉴，这本身就是最强的差异化。

**关键特征**

- 暗色为默认媒介，不是"给亮色套个暗皮"。暗色下**不用投影**，深度完全由表面明度 + 1px 半透明白边构成
- 亮色是暖纸（`#FAF9F6`），不是冷白。这是旧版做对的地方，完整继承
- 英文衬线承担标题，中文无衬线承担信息 —— 分工明确，不混用
- 圆角制度化：卡片 4px（近乎方正），控件 2px，只有导航胶囊与按钮是全圆。方与圆的强对比就是识别度
- 全站唯一的装饰图形是**航迹轨**，而它同时是进度条和章节导航
- 等宽字承担所有数字、编号、标签 —— 数字必须 `font-variant-numeric: tabular-nums`

### 2.4 强调色纪律（硬约束）

> **任意一屏内 `--accent` 的可见使用 ≤ 2 次。**

计入配额的：链接文字、图标着色、焦点环、选中态、当前章节刻度、任何着色的边框或底。

推荐配额分配（每页选一组）：

| 页面 | 配额 1 | 配额 2 |
| :--- | :--- | :--- |
| `/` | 航迹轨当前刻度 | Hero 中文副标题里的一个关键词 |
| `/tracks` | 当前 hover 列的编号 | 页脚 CTA 的下划线 |
| `/tracks/[slug]` | 路线图已完成节点 | 方向编号 `01` |
| `/awards` | 表格里"国家级"三个字 | 航迹轨 |
| `/join` | 焦点环 | 必填标记 |

### 2.5 主按钮为什么不是强调色

**主 CTA 使用中性高对比填充**：亮色下墨底纸字（**16.88:1**），暗色下纸底墨字（**16.87:1**）。

理由有三：

1. 这是全站对比度最高的元素，符合"最重要的东西最显眼"
2. 把强调色从按钮上省下来，才能保住每屏 2 次的配额，让强调色真正稀有
3. 赤陶橙实心底 + 白字在亮色下只有 4.08:1（若用 `#C85F35`），要达标必须压暗到 `#B4522C`——而压暗后它已经接近墨色，不如干脆用墨色

强调色实心按钮作为 `variant="accent"` 保留，全站只在 `/join` 的最终提交按钮使用一次。

### 2.6 禁用色

以下颜色**不得**出现在本项目任何位置：

- `#6366f1` `#4f46e5` `#4338ca` `#3730a3` `#8b5cf6` `#7c3aed` `#a855f7`（Tailwind 默认靛蓝/紫，最可靠的 AI 生成物特征）
- 任何 紫→蓝 / 蓝→青 / 靛→粉 的两段式"信任渐变"
- 纯黑 `#000` 与纯白 `#fff` 作为大面积背景或正文色（`#fff` 仅允许作亮色模式的卡片面）

## 3. 字体

### 3.1 字族

| 角色 | 拉丁 | 中文 | 说明 |
| :--- | :--- | :--- | :--- |
| `--font-display` | **Instrument Serif** 400 | Noto Serif SC 600 | 高对比编辑衬线，只用于超大字号 |
| `--font-sans` | **Geist Sans** 400/500/600 | 系统栈 → `PingFang SC` / `Microsoft YaHei` / `Noto Sans SC` | 正文与 UI |
| `--font-mono` | **Geist Mono** 400/500 | — | 数字、编号、标签、代码、航迹刻度 |

```css
--font-display: 'Instrument Serif', 'Noto Serif SC', Georgia, serif;
--font-sans: 'Geist Sans', -apple-system, 'PingFang SC', 'Microsoft YaHei',
             'Noto Sans SC', system-ui, sans-serif;
--font-mono: 'Geist Mono', ui-monospace, 'SFMono-Regular', Consolas, monospace;
```

### 3.2 中英分工原则（本项目的排版核心决策）

> **英文承担"标识"，中文承担"信息"。**

- 页面标题、区块标题一律是英文衬线（`About.` `Tracks.` `Awards.`），中文标题作为它下方的无衬线副标题
- 中文只在**两处**允许使用衬线：Hero 的中文副标题、每页开头的引言句。且仅限 `Noto Serif SC 600`
- 这么分工的原因：Instrument Serif 是高对比细衬线，与任何中文衬线在同一行并置都会出现明显的笔画粗细断裂。把两者分置于不同层级，断裂就变成了层级差异

### 3.3 字号阶梯

比例 1.25，共 9 级。全部使用 `clamp()` 流式。

| 角色 | 尺寸 | 拉丁 行高 / 字距 | 中文 行高 / 字距 |
| :--- | :--- | :--- | :--- |
| `display-1` | `clamp(3.5rem, 10vw, 8.5rem)` | `0.95` / `-0.03em` | — |
| `display-2` | `clamp(2.5rem, 6vw, 4.5rem)` | `1.0` / `-0.025em` | `1.35` / `0` |
| `h1` | `clamp(2rem, 4vw, 3rem)` | `1.1` / `-0.02em` | `1.35` / `0` |
| `h2` | `clamp(1.5rem, 2.5vw, 1.875rem)` | `1.2` / `-0.015em` | `1.4` / `0` |
| `h3` | `1.25rem` | `1.3` / `-0.01em` | `1.5` / `0` |
| `body-lg` | `1.125rem` | `1.6` / `0` | `1.8` / `0` |
| `body` | `1rem` | `1.6` / `0` | `1.75` / `0` |
| `small` | `0.875rem` | `1.5` / `0.01em` | `1.7` / `0` |
| `caption` | `0.75rem` | `1.5` / `0.02em` | `1.7` / `0` |
| `label`（全大写等宽） | `0.6875rem` | `1.4` / **`0.1em`** | — |

### 3.4 必须遵守的排版规则

1. **中文行高不得低于 1.35（标题）/ 1.7（正文）。** 中文字形填满字身框，用拉丁的 1.0 行高会让相邻两行直接相撞。Hero 的中文副标题即使是 48px 也必须 1.35
2. **负字距是拉丁专属。** 中文已在固定字身框上，`-0.02em` 只会让字挤在一起。中文一律 `letter-spacing: 0`
3. **全大写必须加 `0.1em` 正字距。** 无字距的全大写是最容易识别的业余痕迹
4. **中英混排时，紧的拉丁数值只加在拉丁元素上**，不要从父级继承给中文块
5. **所有数字使用 `font-variant-numeric: tabular-nums`**，避免统计数字在动效或状态切换时抖动
6. **正文阅读宽度上限 68ch**，长文块不得铺满 1200px

### 3.5 字体加载策略

中文字体体积是本项目最大的性能风险。策略：

- **正文中文完全走系统栈**，不下载任何中文字体（`PingFang SC` / `Microsoft YaHei` 覆盖 >95% 目标用户）
- **仅 `Noto Serif SC 600` 做子集化自托管**，只保留标题里实际用到的约 300 个字形（用 `fonttools pyftsubset` 生成，产物 < 40KB）
- Instrument Serif / Geist 通过 `next/font/local` 自托管，`display: swap`，并配置 `adjustFontFallback` 以消除字体切换造成的 CLS
- **不使用 Google Fonts 运行时 CDN**（国内校园网不可靠）

## 4. 间距与栅格

### 4.1 间距标尺

4px 基数：`4 8 12 16 24 32 48 64 96 128 192`

| Token | 值 | 用途 |
| :--- | :--- | :--- |
| `--space-1` … `--space-6` | 4 / 8 / 12 / 16 / 24 / 32 px | 组件内部 |
| `--space-7` … `--space-9` | 48 / 64 / 96 px | 组件之间 |
| `--space-10` `--space-11` | 128 / 192 px | 区块之间 |
| `--section-gap` | `clamp(6rem, 12vh, 10rem)` | 页面区块的标准节奏 |

### 4.2 栅格

- 12 列，最大内容宽 **1200px**（`--container`），左右安全边距 24px（手机）/ 40px（平板）/ 64px（桌面）
- 列间距 24px（<1024px）/ 32px（≥1024px）
- 阅读型区块（About 正文、方向描述）额外限制在 **68ch**
- ≥1920px 时容器放宽到 **1360px**，但阅读宽度**不变**——大屏应该给更多留白，不是更长的行

### 4.3 节奏原则

> **一紧一松交替。** 连续两个"呼吸型"区块之间必须插入一个"密集型"区块。

对称、等密度的排版读起来像模板；密度变化读起来像有人做过决定。首页的 40vh 纯留白缓冲区是这条原则最极端的一次应用。

## 5. 圆角与形状

| Token | 值 | 用于 |
| :--- | :--- | :--- |
| `--radius-xs` | `2px` | 输入框、复选框、标签 |
| `--radius-sm` | `4px` | 卡片、表格、图片、模态框 |
| `--radius-full` | `9999px` | **仅** 导航胶囊与按钮 |

**不使用** 8px / 12px / 16px 中间档。方正的内容容器 + 全圆的交互控件，这种二元对立本身就是识别特征。

**禁止**：圆角卡片 + 左侧彩色竖条的组合（教科书级的"AI 仪表盘卡片"）。

## 6. 深度与层次

### 6.1 暗色：不用投影

暗色下投影几乎不可见，堆叠 `box-shadow` 只会产生脏边。深度靠三件事：

1. **表面明度**：`--bg` → `--surface` → `--surface-2` 三级
2. **1px 半透明白边**：`rgba(255,255,255,0.08)`，悬浮时升到 `0.14`
3. **内高光**：`inset 0 1px 0 rgba(255,255,255,0.06)`，仅用于按钮与导航胶囊的顶边

### 6.2 亮色：单层柔和投影

```css
--shadow-sm: 0 1px 2px rgba(22,24,28,0.05);
--shadow-md: 0 4px 16px -4px rgba(22,24,28,0.08);
--shadow-lg: 0 16px 48px -12px rgba(22,24,28,0.12);
```

最多用到 `--shadow-md`；`--shadow-lg` 仅供模态框。

### 6.3 层级（z-index）

| 层 | z | 内容 |
| :--- | :--- | :--- |
| 基础 | 0 | 页面内容 |
| 航迹轨 | 20 | 左侧刻度轨 |
| 导航 | 40 | 悬浮胶囊 |
| 模态/证书全屏 | 60 | Dialog |
| 跳转链接 / Toast | 80 | 无障碍跳转、提交反馈 |

## 7. 组件规范

### 7.1 按钮

| 变体 | 暗色 | 亮色 | 用于 |
| :--- | :--- | :--- | :--- |
| `primary` | 底 `--fg` / 字 `--bg`（16.87:1） | 底 `--fg` / 字 `--bg`（16.88:1） | 每屏至多一个 |
| `accent` | 底 `--accent` / 字 `--bg`（7.15:1） | 底 `--accent` / 字 `#FFF`（5.02:1） | 全站仅 `/join` 提交 |
| `ghost` | 底 `rgba(255,255,255,0.03)` / 边 `--border` / 字 `--fg` | 底 `transparent` / 边 `--border-strong` / 字 `--fg` | 次级操作 |
| `link` | 字 `--fg` + 1px 下划线，hover 时下划线变 `--accent` | 同 | 正文内链接 |

规格：高 44px（触控最小尺寸）、水平内边距 20px、`--radius-full`、`--font-sans 500`、`0.01em` 字距。

按下反馈：`transform: scale(0.98)`，**80ms**。这是全站最快的动效，也是最常被感知的那一个——值得单独调。

### 7.2 卡片

- 底 `--surface`，边 1px `--border`，圆角 `--radius-sm`（4px）
- 内边距 24px（手机）/ 32px（桌面）
- hover：边框升到 `--border-strong`，**不位移、不放大、不加投影**。位移是廉价的；边框变化是精确的
- 禁止：左侧彩色竖条、内嵌渐变底、彩色图标底

### 7.3 表单控件

- 底 `--surface`，边 1px `--border-control`（暗 3.38:1 / 亮 3.21:1，满足 WCAG 1.4.11）
- 高 44px，圆角 `--radius-xs`（2px），内边距 12px
- 焦点：`outline: 2px solid var(--accent); outline-offset: 2px`（暗 7.15:1 / 亮 4.77:1）
- 错误：边框 `--danger` + 下方 `small` 文字 + `aria-invalid` + `aria-describedby`
- 标签常驻在输入框上方，**不用浮动标签**（浮动标签牺牲可扫描性换取"精致"，不划算）

### 7.4 表格

奖项数据就该用表格。

- 表头：`--font-mono`，`label` 尺寸，全大写 + `0.1em` 字距，`--fg-faint`
- 行分隔：1px `--border`，无竖线
- 斑马纹：亮色用 `--surface-2`，暗色**不用**（明度差在暗色下会显脏），改为悬浮时整行 `--accent-quiet`
- 数字列右对齐 + `tabular-nums`

### 7.5 航迹轨（`TrajectoryRail`）

见 [`03-IA-ROUTES.md`](03-IA-ROUTES.md) §3.2。视觉规格：

- 轨道 1px，色 `--border`
- 已滚过部分：`linear-gradient(to bottom, var(--accent), transparent)`，透明度 0.6
- 刻度点：6px 方形（不是圆点），未读描边、已读实心
- 编号标签：`--font-mono`，`caption` 尺寸，`0.06em` 字距
- 当前项：刻度 `--accent`，标签 `--fg`，其余标签 `--fg-faint`

### 7.6 标签 / Chip

技术栈关键词用：`--font-mono` + `caption` + 1px `--border` + `--radius-xs` + 内边距 4/8px。

**不着色**。五大方向不分配五种颜色——那会立刻引入五个"第二强调色"。方向的区分靠编号与位置，不靠颜色。

## 8. 响应式

| 断点 | 宽度 | 变化 |
| :--- | :--- | :--- |
| `sm` | < 640px | 单列；航迹轨 → 顶部 2px 进度条；导航 → 汉堡全屏面板；`display-1` 降到 3.5rem |
| `md` | 640–1023px | 双列网格；容器边距 40px |
| `lg` | 1024–1279px | `/tracks` 五列降为 3+2；航迹轨仍隐藏 |
| `xl` | 1280–1919px | 完整布局；**航迹轨出现** |
| `2xl` | ≥ 1920px | 容器放宽到 1360px，阅读宽度保持 68ch，留白变多 |

**移动端专项**：

- 所有触控目标 ≥ 44×44px
- hover 类交互必须有触屏等价物，或在移动端明确取消
- 移动端动画时长比桌面短 20–30%（移动距离更短，同样时长会显得拖沓）
- 航迹轨在 `<1280px` 转为吸顶的「移动端航迹条」（编号 + 章节名 + 2px 进度），签名元素不在主场缺席

> 移动端是本项目的主场（招新入口是二维码与海报）。完整规格见 **[`09-MOBILE.md`](09-MOBILE.md)** —— 含断点细分、悬停交互清算表、微信/QQ 内置浏览器约束、逐页布局重构与实机测试矩阵。

## 9. Do / Don't

### Do

- ✅ 用留白建立层级，而不是用背景色块
- ✅ 表格就用表格，列表就用列表
- ✅ 中文行高 ≥1.7（正文）/ ≥1.35（标题）
- ✅ 全大写加 `0.1em` 字距
- ✅ 每屏 `--accent` ≤ 2 次
- ✅ 数字用等宽 + `tabular-nums`
- ✅ hover 改边框，不改位置
- ✅ 让一个页面上有一处"不按常理出牌"的细节

### Don't

- ❌ 紫蓝渐变、霓虹发光、赛博网格背景
- ❌ Emoji 当功能图标（用 1.6–1.8px 描边的单色 SVG，`currentColor`）
- ❌ 编造数据（"效率提升 10 倍""99.9% 可用"）
- ❌ 占位文案（`lorem ipsum`、"特性一/二/三"）
- ❌ 外部占位图 CDN（`unsplash` / `placehold.co` / `picsum`）
- ❌ 装饰性 blob / 波浪 SVG 背景
- ❌ 圆角卡片 + 左侧彩色竖条
- ❌ 五个方向配五种颜色
- ❌ `:root` 之外出现超过 12 个裸十六进制色值
- ❌ 完全对称、等密度的版面

## 10. 给 AI 助手的实现提示

在本项目里生成任何 UI 代码前，先确认：

```
1. 颜色是否全部来自 var(--*)？裸十六进制超过 12 个即为违规
2. 这一屏 --accent 出现几次？>2 就砍
3. 中文文本的 line-height 是否 ≥1.7（正文）/ ≥1.35（标题）？
4. 中文是否被施加了负 letter-spacing？有就删
5. 全大写文本是否有 0.1em 字距？
6. 新加的动画会不会成为这一页的第二个记忆点？会就不加
7. 这个动画有没有 prefers-reduced-motion 降级？
8. 交互元素是否 ≥44×44px、有可见焦点环、可键盘操作？
9. 文案是不是真实数据？拿不到就整块不上，不编
10. 卡片 hover 是不是又写成了 translateY？改成边框变化
```

**引用而非重定义**：所有值从 [`design/tokens.css`](../design/tokens.css) 取用。若某个值不存在，先在 tokens 里加，再用——不要在组件里硬写。
