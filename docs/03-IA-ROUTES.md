## 3. 全局框架

### 3.1 导航（`SiteHeader`）

保留旧版的**胶囊悬浮导航**（这是旧版做对的地方），但改造：

```
┌─────────────────────────────────────────────────────────┐
│  [YFY Logo]        关于  方向  作品  荣誉        [☾] [加入]│
└─────────────────────────────────────────────────────────┘
        ↑ 左上角常驻                    右侧胶囊 ↑
```

- 桌面：Logo 独立在左上角，导航项 + 主题切换 + CTA 组成右侧一个胶囊，`backdrop-filter: blur(16px)`- 「加入」是唯一的实心 CTA，全站统一样式，是每屏 `--accent` 的两次配额之一
- 当前路由用**下方 1px 短横线**标记，不用背景高亮（更克制）
- 滚动超过 80px 时胶囊高度从 56px 收到 48px，边框透明度从 0.08 升到 0.14。仅此一处滚动响应，220ms
- 移动端：Logo + 汉堡按钮；点开为全屏面板，导航项交错入场（stagger 40ms，仅 4 项，符合"只对小组做交错"）

### 3.2 航迹轨（`TrajectoryRail`）— 全站签名元素

```
桌面端（≥1280px），固定在左侧 40px 处：

  │
  ├─ 01   ← 已读章节：刻度实心，标签 100% 不透明
  │
  ├─ 02   ← 当前章节：刻度实心 + 强调色，标签放大到 12px
  │
  ├─ 03   ← 未读章节：刻度描边，标签 40% 不透明
  │
  ├─ 04
  │
```

- 轨道本体是 1px 竖线；已滚过的部分用 `--accent` 到透明的渐变填充（这是全站"效果层"渐变的两处之一）
- 刻度点可点击 → 平滑滚到对应区块（`scroll-margin-top` 处理定位）
- 实现：原生 CSS 滚动驱动动画 `animation-timeline: scroll()`，**零 JS**；不支持的浏览器保持静态展示（渐进增强，非降级）
- `<1280px` 时轨道隐藏，改为吸顶的**移动端航迹条**（28px：`03 / 05` 等宽编号 + 章节名 + 2px 进度轨，点击展开章节列表）。签名元素不能在移动端主场缺席 —— 见 [`09-MOBILE.md`](09-MOBILE.md) §3
- 语义：`<nav aria-label="页面章节">` + `<ol>`，每项 `aria-current="true"`

它同时是装饰、进度、导航——因此它是全站**唯一**被允许存在的装饰性图形。

### 3.3 页脚（`SiteFooter`）

保留旧版的低调气质与「Code by Dawn」署名彩蛋（这是有灵魂的细节，是"只有做过这个产品的人才会放的东西"）。

- 三列：品牌与口号 / 站点导航 / 联系与加入（QQ 群、GitHub、学院链接）
- 底部单行：`云飞扬社团 · Est. 2014 · 南阳理工学院计算机与软件学院 · Code by Dawn`
- 彩蛋保留：连点署名 5 次进入 Blueprint 蓝图模式（10 秒后自动还原）

**设计要点**

- ①→② 之间的 40vh 纯留白是刻意的：旧版的"情绪换挡缓冲区"是好设计，保留并放大

- ③ 打破常规网格：五条方向是**五行横排**而非卡片网格。"hover 时其他行变暗"是聚焦而非放大自身——反直觉，也更克制

**记忆点动效**：③ 路线图的 SVG 路径随滚动绘制（`stroke-dashoffset` 绑定滚动进度），节点在被路径触及的**那一帧**从描边变实心。**路径在大三处分成两条**——这是整页最后也最重的一个画面：你读完这条方向的三年，看到的是路分岔了。

**为什么值得**：它在语义上就是"你会怎么走过这三年，以及最后往哪走"，动效在描述一条真实的路径——符合"动效必须有语义"的原则。

技术细节放在技术栈标签**之前**是刻意的：`Vue 3 · TypeScript` 这种标签谁都能贴，"用 Bareiss 消元抑制中间分数膨胀"才是真正说明水平的东西。别让它被一排 chip 淹没。

**记忆点动效 · 底片**：卡片默认是低饱和的（`filter: saturate(0.25)`），hover 时**只有光标周围 200px 半径内恢复彩色**——通过 CSS `mask-image: radial-gradient()` + `--mx/--my` 自定义属性实现，指针移动只改两个 CSS 变量，不触发布局或重绘 layout。

像用手电筒扫过一叠底片。触屏设备上没有 hover，改为卡片整体在进入视口时一次性恢复彩色（220ms）。

**卡片可点进详情页**：内容撑得住的项目（矩阵计算器、智光耀城）整卡链接到 `/works/[slug]`；其余项目卡片只提供外链，不假装有详情页。

### 4.6 `/works/[slug]` 作品详情

> **职责**：把一个项目从"一张卡片"变成"一份可核实的工程记录"。模板由数据驱动，各项目共用。

```
① 项目头        矩阵计算器 · 精确有理数
                Exact Rational Matrix Calculator
                纯前端矩阵计算器，BigInt 有理数内核，
                整个计算过程零浮点误差

                已上线 · 2026-01 — 2026-07
                [ 打开使用 ↗ ]   [ 源码 ↗ ]

② 截图对照 ★     ┌────────────╫────────────┐
                │  暗色截图   ║  亮色截图   │  ← 中间可拖动的分隔手柄
                └────────────╫────────────┘

③ 它解决什么     2–3 段，写给不懂这个领域的人看
                矩阵计算器：浮点为什么会出错、有理数内核为什么重要
                智光耀城：城市照明运维实际要处理什么

④ 怎么做的      技术栈（分层列出，不是一排彩色 chip）
                + 关键工程决策，每条附一句为什么：
                · 行列式用 Bareiss 消元 —— 抑制精确运算的分数膨胀
                · 特征多项式用 Faddeev–LeVerrier
                · core / algorithms 不依赖 Vue —— 内核可独立测试
                · 行变换存为事件而非矩阵副本 —— 长推导不撑爆内存
                · OpenAPI → Orval 生成客户端 —— 接口契约单一真源
                · SSE 推送业务事件 —— 不轮询

⑤ 怎么保证对    质量证据。这一块是这两个项目最硬的部分
                矩阵计算器：性质测试（RREF 幂等 / det(AB)=det(A)det(B)
                          / A·A⁻¹=I / PA=LU）+ 独立 Python 交叉验证
                智光耀城：195 后端测试 · 425 前端测试 · 9 条 E2E
                        · 键盘可访问性 / 1024·1280 视口 / 200% 缩放

⑥ 边界          做不到什么，如实写
                矩阵计算器：100×100 上限、伴随 8 阶、MathJax 走 CDN、
                          特征值/QR/SVD 未混入有理数内核
                智光耀城：全部为模拟数据，不连接真实灯杆；
                        V1.0 范围外的一长串

⑦ 关联          相关技术方向（链到 /tracks/[slug]）
                相关竞赛奖项（如有）

⑧ 换项目        ← 上一个作品            下一个作品 →

⑨ CTA          想做出下一个？  [ 加入我们 ]
```

**⑥ 为什么必须存在**：一个项目页只写优点，读起来像宣传册；写清楚边界，读起来像工程报告。对懂行的读者（老师、评审、企业），"知道自己做不到什么"本身就是能力的一部分。这是内容真实性红线的直接体现——尤其智光耀城的"全部为模拟数据"，必须写在页面上，不能藏。

**⑤ 的数字要照抄**：195 / 425 / 9 是项目自身的归档验收记录。不要四舍五入成"两百多项测试"，也不要升级成"持续通过"——原项目 README 自己就限定了这是归档基线。

**记忆点动效 · 对照（Compare）**：② 的明暗截图对比滑块。

- 同一界面的暗色与亮色截图叠放，上层用 `clip-path: inset(0 0 0 var(--split))` 裁切
- 拖动手柄只更新 `--split` 一个 CSS 变量，不触发布局
- **全站唯一一处手势驱动、位置跟随的动效**——机制上与其他七个记忆点完全不同，因此不构成重复
- 语义真实：这两个项目都实现了完整的明暗双主题，本身就是工程完成度的证据；而本站自己也是双主题，形成呼应
- 键盘等价：手柄可聚焦，`←`/`→` 每次移动 5%，`Home`/`End` 到两端
- `touch-action: pan-y` —— 横向拖手柄，纵向仍可正常滚动页面
- **只有一张截图时不渲染滑块**，退化为静态图。不为了动效硬造第二张图

🔴 依赖：每个项目两张同视角截图（暗色 + 亮色）。两个项目都有双主题，补图成本很低。

### 4.8 `/join` 加入

> **职责**：消除犹豫，然后收到报名。这是全站转化的终点，也是 P0 用户最终要落地的地方。

```
① 页面标题       Join. / 登机口
                「我们要的不是已经会的人，是想学会的人。」

② 我们在找什么    ✓ 愿意每周投入固定时间
                ✓ 能接受打卡、考核、退出机制
                ✓ 对某个方向有真实好奇心
                ✗ 想混学分 / 想加社团经历的
                → 正反并列。明确说"不适合谁"比只说"欢迎所有人"
                  更能筛出对的人，也更可信

③ 招新流程       ① 报名 → ② 笔试/代码基础 → ③ 面试 → ④ 试用期
                🔴 需要真实时间节点与每轮考核形式

④ 成员怎么说      2–3 条现役成员的一句话
                🔴 需要征集
                → 拿不到就整块不上，不编

⑤ 常见问题       零基础可以报吗？
                需要投入多少时间？
                和其他社团/工作室有什么不同？
                考核不通过会怎样？
                🔴 答案需负责人确认

⑥ 报名表 ★       姓名 / 年级专业 / 联系方式（QQ 或手机）
                / 意向方向（五选一）/ 一句话：你想做什么
                [ 提交报名 ]

⑦ 其他入口       QQ 迎新群二维码（沿用现有 SVG）
                招新海报（点击查看大图）
```

**记忆点动效 · 盖章**：提交成功时，按钮区域被一枚"已收到"印记替换——`scale(1.06) → scale(1)` + 透明度，180ms，**一次**。没有 confetti、没有粒子、没有循环。

**表单微反馈规范**：
- 失焦校验（`onBlur`），不是输入时实时报错
- 错误状态用**边框色 + 下方文字**，150ms 颜色过渡，**绝不抖动**（抖动是惩罚性的，且触发前庭不适）
- 提交中：按钮文字换成"提交中…"，宽度锁定不跳动
- 每个错误 `aria-describedby` 关联，`aria-invalid`，首个错误自动聚焦

**二维码的反常规细节**：hover 时二维码本身**不放大**，而是四角的取景框标记向外扩张 4px——相机取景器隐喻，暗示"扫我"。

**移动端整段重做**：用户正用手机看这个页面，没法扫自己的屏幕。⑦ 在移动端改为「一键加入 QQ 群」深链 → 长按识别二维码 → 复制群号，三级降级。微信内禁止唤起 QQ 深链，所以「复制群号」必须始终可见。见 [`09-MOBILE.md`](09-MOBILE.md) §6.3。

## 5. 每页动效人格速查

| 页面 | 记忆点（唯一） | 静止程度 | 反常规细节 |
| :--- | :--- | :--- | :--- |
| `/` | 标题显影光带 | 极高，只有滚动指示器呼吸 | 数字**不做** count-up |
| `/about` | 编年史年份点亮 | 高 | 老师卡 hover：主体静止、背景视差 |
| `/tracks` | 五线分流 | 极高，入场后完全静止 | hover 时**其他四列变暗** |
| `/tracks/[slug]` | 路线图随滚动绘制，终点分岔 | 中 | 节点在路径触及那一帧变实心 |
| `/works` | 光标聚光显色 | 高 | 默认低饱和，是"底片"不是"卡片" |
| `/works/[slug]` | 明暗截图对照滑块 | 高 | 全站唯一手势驱动动效；只有一张图就不做 |
| `/awards` | 证书共享元素放大 | **完全静止** | 全页零 hover 变换 |
| `/join` | 提交盖章 | 高 | 二维码 hover：取景框扩张，本体不动 |

**这张表的意义**：任何新增动效的提案，都必须先回答"它会不会成为这一页的第二个记忆点"。如果会，砍掉其中一个。

**移动端形态**：其中三项需要重构而非缩放（`/tracks` 分流改纵向、`/tracks/[slug]` 路线图改纵向、`/join` 二维码整段重做），三项 hover 依赖项需要触屏等价物或明确取消。见 [`09-MOBILE.md`](09-MOBILE.md) §4–§5。

## 6. 跨页导航与过渡

- 使用 **View Transitions API** 做跨路由过渡：默认 crossfade 180ms
- `/tracks` → `/tracks/[slug]`：方向编号 `01` 使用 `view-transition-name="track-01"` 做共享元素飞入
- `/awards` 列表 → 证书全屏：同上
- 不引入自定义平滑滚动库（Lenis 等）：它破坏原生滚动手感、干扰 CSS 滚动驱动动画、增加包体、对辅助技术不友好
- `prefers-reduced-motion` 下跳过 `startViewTransition`（View Transitions **不会**自动应用该媒体查询，必须显式处理）
