# 00 · 产品需求文档（PRD）

> 云飞扬社团官网 v4 · 代号 Trajectory
> 版本 1.0 · 2026-08-18

---

## 1. 背景与问题

云飞扬社团成立于 2014 年，隶属南阳理工学院计算机与软件学院，是一个 36–39 人规模、三年梯队制的学生技术组织。现有官网（v3）是一个 Nuxt 单页情绪落地页，视觉品味不错，但存在四个结构性问题：

| # | 问题 | 后果 |
| :-- | :--- | :--- |
| P1 | **信息全部压在一页**，About / Tech / 成就 / 加入 各占一屏 | 每块内容都只能给一两段话，五大技术方向被压缩成五张卡片，招新最需要的"能学到什么、怎么考核、几年后是什么样"完全讲不清 |
| P2 | **动效无预算约束**，跑马灯 + 滚动揭示 + 视差同时存在 | 观感是"都在动"而不是"设计过"，低端设备掉帧，也稀释了真正该被记住的那个瞬间 |
| P3 | **招新表单走客户端 EmailJS** | 密钥暴露在前端、无反机器人、无提交记录留存、无法统计转化 |
| P4 | **内容硬编码在 Vue 组件模板里** | 换届后学弟学妹要改一条奖项得去改 `.vue` 文件，交接成本高 |

## 2. 目标

### 2.1 首要目标

> **让一个大一新生在 3 分钟内决定报名，并且知道自己报的是什么。**

这句话决定了所有取舍。当"好看"和"讲清楚"冲突时，讲清楚优先；当"讲清楚"和"讲得多"冲突时，讲清楚优先。

### 2.2 次要目标

1. **对外可作为社团名片** —— 校内评优、企业合作、赛事答辩时可直接甩链接
2. **可被换届接手** —— 内容改动不需要碰组件代码，新维护者半天内能上手
3. **成为社团的技术门面** —— 站点本身就是一份作品集，代码质量与工程规范经得起看

### 2.3 明确的非目标

- ❌ 不做会员系统 / 登录 / 后台管理（36 人规模不需要，维护成本远超收益）
- ❌ 不做博客 / 技术文章平台（社团已有其他分享渠道，且更新压力会让站点烂尾）
- ❌ 不做完整英文站（英文只作为排版元素与 SEO 元数据存在）⚪ Phase 2
- ❌ 不追求"炫技动效展示"（用户明确要求克制、精雕细节、出其不意，而非跑马灯堆砌）

## 3. 目标用户

| 优先级 | 用户 | 来源场景 | 核心疑问 | 站点必须回答 |
| :--- | :--- | :--- | :--- | :--- |
| **P0** | 大一新生（招新季） | 迎新群二维码 / 学长安利 / 宣传海报 | "这里能学到什么？我这种零基础能进吗？进去要做什么？" | `/tracks` 五方向 + 成长路线图；`/join` 流程与考核；`/about` 梯队与师徒制 |
| **P1** | 大二/大三转入者 | 校内搜索 / 同学推荐 | "有没有我这个方向？做过什么真项目？" | `/tracks/[slug]` 技术栈深度；`/works` 已上线项目 |
| **P2** | 学院老师 / 评审 | 评优材料 / 答辩 | "这个组织的产出是什么？" | `/awards` 竞赛成果；`/works` 项目；`/about` 组织机制 |
| **P3** | 企业 / 外部合作方 | 搜索引擎 / 名片 | "这帮人的技术水平如何？" | 整站的工程质量本身 + `/works` |
| **P4** | 社团现役成员 | 内部认同 | "我是这个组织的一部分" | `/about` 文化；页脚署名与彩蛋 |

**设计取向**：P0 是绝对重心。首页存在的唯一意义是把 P0 用户在 8 秒内推向 `/tracks` 或 `/join`。

## 4. 信息架构总览

六条顶层路由。详细逐屏结构见 [`03-IA-ROUTES.md`](03-IA-ROUTES.md)。

```
/                    起点      品牌情绪入口 · 8 秒内建立"这里值得看"
├── /about           关于      我们是谁 · 故事 / 文化 / 机制 / 梯队 / 编年史
├── /tracks          方向      五条航道总览
│   └── /tracks/[slug]         单方向详情 · 技术栈 / 三年成长路线（大三分流）/ 代表产出
├── /works           作品      做过什么 · 已上线项目 / 孵化项目
│   └── /works/[slug]          项目详情 · 怎么做的 / 怎么保证对 / 边界在哪
├── /awards          荣誉      证明实力 · 竞赛档案柜
└── /join            加入      登机口 · 招新流程 / 考核标准 / FAQ / 报名表
```

**为什么拆页而不是继续单页**：

1. 每页可以有**独立的动效人格**——这是"出其不意"的前提。单页只能用一套动效语言，多页可以让用户每进一个新页面都被小小地惊到一次。
2. 每页可以有**独立的 SEO 落地页**——"南阳理工 人工智能 社团" 应该落到 `/tracks/ai` 而不是首页锚点。
3. 内容可以**长到该有的长度**——五大方向每个值一整页，压在卡片里是浪费。
4. 分享链接更精准——招新时直接发 `/join`，答辩时直接发 `/awards`。

## 5. 功能需求

### 5.1 P0 · 必须有（M1–M3 交付）

| ID | 功能 | 说明 | 验收 |
| :-- | :--- | :--- | :--- |
| F-01 | 六条路由的静态页面 | 见 IA 文档 | 全部路由可访问，无 404，无 CLS |
| F-02 | 明/暗双主题 | 系统跟随 + 手动切换 + `localStorage` 持久化 + 无 FOUC | 首屏无主题闪烁；刷新保持选择 |
| F-03 | 航迹轨（Trajectory Rail） | 左侧刻度轨，兼滚动进度与章节导航 | 桌面端常驻；移动端降级为顶部 2px 进度条 |
| F-04 | 五方向内容体系 | 总览页 + 5 个详情页，含技术栈、三年路线图（**大三分流为就业 / 考研**）、成长目标 | 每个方向 ≥400 字实质内容，不得占位 |
| F-04b | 作品详情页 | 内容撑得住的项目开详情页（矩阵计算器、智光耀城），含工程决策、质量证据、**项目边界** | `detail.limits` 为必填，只写优点的页面构建失败 |
| F-05 | 竞赛荣誉档案柜 | 证书卡片 → 点击全屏查看（共享元素过渡） | 键盘可操作，`Esc` 关闭，焦点正确归还 |
| F-06 | 招新报名表 | 服务端校验 + Turnstile + 通知投递 | 密钥不出现在客户端产物；重复提交有防护 |
| F-07 | 内容数据外置 | 所有文案/数据在 `content/` 下的 TS 模块，Zod 校验 | 改一条奖项不需要碰 `.tsx` |
| F-08 | 移动端完整适配 | 移动端是主场（招新入口为二维码/海报），含微信/QQ 内置浏览器。详见 [`09-MOBILE.md`](09-MOBILE.md) | 320–430px 无横向滚动；触控目标 ≥44×44px；微信/QQ 内置浏览器实机通过 |
| F-09 | 可访问性基线 | WCAG 2.2 AA | axe 零 serious/critical；纯键盘可走完全部关键路径 |
| F-10 | `prefers-reduced-motion` 降级 | 所有 transform 类动效可关 | 开启后无位移动画，仅保留透明度过渡 |

| 指标 | 目标 | 测量方式 |

## 8. 约束

| 类型 | 约束 |
| :--- | :--- |
| **团队** | 维护者为学生，人数少、有课业压力 → 技术选型必须是主流、文档好、能长期维护的；不引入冷门依赖 |
| **交接** | 每年换届 → 内容与代码必须解耦，且 `README` 要能让新人独立跑起来 |
| **成本** | 学生社团，预算接近零 → 全部依赖必须有免费额度；托管走 Vercel / Cloudflare / EdgeOne 免费层 |
| **网络** | 用户在国内校园网 → 不得依赖 Google Fonts 等境外 CDN 的**运行时**加载；字体自托管 |
| **设备** | **P0 用户几乎全部从手机首次访问**（QQ 群二维码 / 纸质海报扫码），且很大比例在微信/QQ 内置浏览器里；校园内大量千元级安卓机 → 移动端优先设计；首屏 JS ≤ 120KB gzip（移动端）；不引入 WebGL 主视觉 |
| **内容真实性** | 严禁编造数据、奖项、成员数量、指标 | 见 [`08-QUALITY.md`](08-QUALITY.md) 内容真实性红线 |

## 9. 验收标准（Definition of Done）

一个页面被认为完成，需同时满足：

- [ ] 桌面 / 平板 / 手机三档视觉稿实现无偏差
- [ ] 移动端 320px 无横向滚动；所有 hover 交互有触屏等价物或已明确取消
- [ ] 微信 / QQ 内置浏览器实机验证通过
- [ ] 明暗两个主题都检查过，无对比度不足、无色彩反转错误
- [ ] 该页的**唯一记忆点动效**已实现，且同屏无第二个并发动画
- [ ] `prefers-reduced-motion: reduce` 下页面仍完整可用
- [ ] 纯键盘可走完该页全部交互，焦点环可见，Tab 顺序符合视觉顺序
- [ ] axe DevTools 扫描零 serious / critical
- [ ] 该页所有文案来自 `content/`，无组件内硬编码字符串
- [ ] 该页无占位文案、无编造数据、无外部占位图 CDN
- [ ] `--accent` 在任意一屏出现次数 ≤ 2
- [ ] Lighthouse 移动端性能 ≥ 90、可访问性 = 100

## 10. 风险

| 风险 | 影响 | 应对 |
| :--- | :--- | :--- |
| 内容缺口迟迟补不齐 | 页面空壳、被迫上占位文案 | M1 阶段就把缺口清单派给内容负责人，设截止日；到期未交的模块直接不上线，而非填假内容 |
| 动效实现耗时超预期 | 挤压内容与无障碍工作 | 记忆点动效逐页独立，任何一个做不完就退化为静态出现，不阻塞发布 |
| 换届后无人维护 | 站点腐化 | 内容数据外置 + `CONTRIBUTING` 文档 + 数据文件带 Zod schema 报错提示 |
| 国内访问速度 | 首屏慢 | 字体自托管 + 子集化；托管选支持国内加速的平台；图片全部 AVIF/WebP + `next/image` |
| 表单被机器人刷 | 垃圾数据淹没真实报名 | Turnstile + 服务端速率限制 + 蜜罐字段 |
