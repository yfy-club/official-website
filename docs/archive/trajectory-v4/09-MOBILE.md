# 09 · 移动端适配

> **移动端不是"小屏版本"，是这个站点的主场。**
> 招新的主入口是 QQ 群二维码与纸质海报——扫码进来的几乎全部是手机，且很大比例在微信/QQ 内置浏览器里。

---

## 1. 为什么移动端优先级最高

| 入口 | 设备 | 浏览器 |
| :--- | :--- | :--- |
| QQ 迎新群二维码 | 手机 | QQ 内置浏览器 |
| 纸质招新海报扫码 | 手机 | 微信 / QQ 扫一扫 → 内置浏览器 |
| 学长转发链接 | 手机 | 微信内置浏览器 |
| 校内搜索 / 评优答辩 | 桌面 | Chrome / Edge |

P0 用户（大一新生）**几乎不会用电脑第一次访问这个站**。因此：

- 任何"桌面上好看、手机上凑合"的设计都是失败的
- 任何依赖 hover 的交互都必须有触屏等价物，或者干脆在移动端不存在
- 微信/QQ 内置浏览器是**必须实机验证**的目标环境，不是"顺便看看"

## 2. 断点与视口

### 2.1 断点

| 名称 | 范围 | 典型设备 |
| :--- | :--- | :--- |
| `xs` | 320–374px | iPhone SE、老旧安卓 |
| `sm` | 375–639px | **主力区间**：iPhone 14/15、多数安卓 |
| `md` | 640–1023px | 大屏手机横屏、平板竖屏 |
| `lg` | 1024–1279px | 平板横屏、小笔记本 |
| `xl` | 1280–1919px | 桌面（航迹轨出现） |
| `2xl` | ≥1920px | 大屏桌面 |

**设计基准宽度 390px**（iPhone 14/15 逻辑宽度）。所有移动端稿子按 390 画，然后验 320 不溢出、验 430 不空旷。

### 2.2 视口单位

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
```

**禁用 `100vh`。** 移动浏览器的地址栏会收起/展开，`100vh` 会导致首屏在滚动时高度跳变。

| 场景 | 用 |
| :--- | :--- |
| Hero 全屏高度 | `min-height: 100svh`（小视口高度，地址栏展开时的稳定值） |
| 全屏模态 / 移动菜单 | `height: 100dvh`（动态跟随） |
| 需要"至少占满"的装饰区 | `100lvh` |

### 2.3 安全区

iPhone 刘海/灵动岛与底部横条，安卓的手势条：

```css
.site-header { padding-top: max(var(--space-3), env(safe-area-inset-top)); }
.site-footer { padding-bottom: max(var(--space-8), env(safe-area-inset-bottom)); }
.mobile-nav-panel {
  padding: env(safe-area-inset-top) env(safe-area-inset-right)
           env(safe-area-inset-bottom) env(safe-area-inset-left);
}
```

配合 `viewport-fit=cover` 使用。横屏时 `safe-area-inset-left/right` 也非零，不要只处理上下。

## 3. 移动端航迹条

**问题**：航迹轨（全站签名元素）在 `<1280px` 时隐藏。而移动端是主场——签名元素在主场缺席，等于没有签名元素。

**解法**：不是简单换成一根进度条，而是把"刻度 + 编号"的语义压缩进一条吸顶细条。

```
┌────────────────────────────────────────┐
│ [Logo]                          [☰]    │  ← header, 56px
├────────────────────────────────────────┤
│ 03 / 05   五条航道        ▓▓▓▓▓▓░░░░░░ │  ← 航迹条, 28px
└────────────────────────────────────────┘
```

- 高 28px，吸附在 header 下方，随页面滚动常驻
- 左侧：`--font-mono` 的 `03 / 05` 编号 + 当前章节名（`--text-caption`）
- 右侧：2px 进度轨，已滚过部分用 `--rail-fill`
- 编号与章节名切换时**只做透明度交叉淡入**（150ms），不做数字滚动、不做位移
- 实现同桌面：CSS 滚动驱动动画，零 JS
- 点击整条 → 展开章节列表（Radix Dialog，从顶部滑入），点选跳转

这样等宽编号与刻度进度的识别度在移动端被完整保留，只占 28px。

## 4. 悬停依赖的交互 → 触屏等价物

这是移动端适配里**最容易被漏掉**的一环。全站所有 hover 交互逐条清算：

| 位置 | 桌面 hover 行为 | 移动端 |
| :--- | :--- | :--- |
| 首页 ③ 五条航道 | 该行左移 8px，其余四行降到 40% | **取消**。改为整行可点，`:active` 时背景 `--accent-quiet`，80ms |
| `/tracks` 五列 | 其余四列降到 30% | **取消**。单列纵向排列，无需聚焦机制 |
| `/works` 底片聚光 | 光标半径 200px 内恢复彩色 | **进入视口时一次性恢复彩色**（220ms，`IntersectionObserver`，触发后断开） |
| `/about` 老师卡背景视差 | 背景网格位移 2px | **不做替代，直接取消**。它是 hover 专属彩蛋，没有等价物就不该硬造一个 |
| `/join` 二维码取景框 | 四角标记外扩 4px | **整个交互重做**，见 §6.3 |
| 卡片 hover 边框变化 | `--border` → `--border-strong` | 改为 `:active` 态，80ms |
| 链接 hover 下划线变色 | 下划线 → `--accent` | 改为 `:active` 态 |

**统一规则**：

```css
/* 只在真正支持 hover 的设备上启用 hover 样式 */
@media (hover: hover) and (pointer: fine) {
  .card:hover { border-color: var(--border-strong); }
}
/* 触屏设备用按下反馈 */
@media (hover: none) {
  .card:active { background: var(--accent-quiet); }
}
```

**不要用屏幕宽度判断有无 hover。** 触屏笔记本存在，用 `@media (hover: hover)` 才是对的。

## 5. 记忆点动效的移动端形态

| 页面 | 桌面记忆点 | 移动端 |
| :--- | :--- | :--- |
| `/` | 标题显影光带 1100ms | **保留**，时长缩到 **850ms**（移动端动画比桌面短 20–30%） |
| `/about` | 编年史年份点亮 | **保留**。时间轴从横向改为**纵向**，年份在左、事件在右 |
| `/tracks` | 五线横向分流 700ms | **重构为纵向**，见下 |
| `/tracks/[slug]` | 路线图随滚动绘制、终点分岔 | **保留**。路径从横向改为纵向；大三的两条支线在竖屏下左右并排展开 |
| `/works` | 光标聚光 | 换为进入视口一次性显色 |
| `/works/[slug]` | 明暗截图对照滑块 | **保留，且在移动端更自然**——触屏拖动比鼠标拖动更直觉。必须设 `touch-action: pan-y` |
| `/awards` | 证书共享元素放大 | **保留**（View Transitions 不支持时降级为 Dialog 淡入） |
| `/join` | 提交盖章 180ms | **保留**，缩到 140ms |

### `/tracks` 分流动画的纵向重构

桌面是"从顶部一点向下分叉到五列"。移动端单列排布时这个隐喻不成立，需要重画而不是缩放：

```
  ●            ← 起点
  ├──── 01 人工智能
  ├──── 02 软工智能
  ├──── 03 数据库
  ├──── 04 智能云物联
  └──── 05 工业数智化
```

一条主干竖线从顶部绘下（`stroke-dashoffset`，500ms），五条支线**同时**向右展开（不交错——五个方向是平权的）。像地铁线路图的分支站点。

概念（航迹分叉）完整保留，形态适配了竖屏。这比把桌面 SVG 等比缩小到 390px 宽要好得多——后者线条会挤成一团。

## 6. 逐页移动端布局

### 6.1 `/` 首页

| 区块 | 移动端 |
| :--- | :--- |
| ① Hero | `min-height: 100svh`。标题 `display-1` 取 `3.5rem`；"We Code" / "the Future" 强制两行。副标题与 CTA 上移，确保**首屏内能看到至少一个 CTA**——不能让人必须滚动才知道能干什么 |
| ① CTA | 两个按钮**纵向堆叠**，各占满宽度，间距 12px。不做并排——390px 下并排会让文字换行 |
| ② 数字断言 | 2×2 网格（不是 1×4，那太长）。数字 `--text-h1`，标签 `--text-caption` |
| ③ 五条航道 | 五行纵向，每行整块可点，行高 ≥64px |
| ④ 一件真事 | 图在上、文在下（桌面是左右分栏）。截图按 16:9 显示，`next/image` 的 `sizes="100vw"` |
| ⑤ CTA | 单个满宽按钮 |
| ①→② 之间的 40vh 留白 | **缩到 20vh**。移动端滚动成本更高，过长的空白会被误认为页面结束 |

### 6.2 `/awards` 表格的移动端形态

赛事总览是 6 行 × 3 列的表格。**不要做横向滚动表格**——横向滚动在移动端是最糟糕的模式之一（易误触、看不全、与页面纵向滚动打架）。

改为**堆叠式条目**：

```
┌──────────────────────────────────┐
│ 全国大学生智能汽车竞赛              │  ← 竞赛名，--text-body 500
│ 国家级 / 省级                      │  ← 级别，--font-mono --text-caption
│ 国家级二等奖 · 省级一等奖           │  ← 结果，--fg-muted
└──────────────────────────────────┘
```

语义仍用 `<table>` + `display: block` 重排，或用 `<dl>`。**不要**用一堆 `<div>` 丢掉表格语义。

证书档案柜：桌面 3+2 网格 → 移动端 **2 列网格**（不是单列，证书是图片，单列会让每张占满屏幕导致翻找困难）。

### 6.3 `/join` 二维码 — 移动端必须重做

**核心问题**：用户正在用手机看这个页面，**没法用同一台手机扫自己屏幕上的二维码**。

桌面端展示二维码是对的（用手机扫电脑屏幕）。移动端展示二维码基本是无效的。

移动端方案：

```
┌──────────────────────────────────┐
│  [ 一键加入 QQ 迎新群 ]            │  ← 主按钮，深链直接唤起 QQ
│                                  │
│  或长按下方二维码识别               │  ← 次要提示
│  ┌────────┐                      │
│  │ QR码   │                      │  ← 缩小展示，作为兜底
│  └────────┘                      │
│  群号：xxxxxxx  [ 复制 ]           │  ← 最终兜底：复制群号
└──────────────────────────────────┘
```

三级降级：**深链唤起 QQ → 长按识别二维码 → 复制群号手动搜索**。

- 深链在微信内置浏览器里会被拦截（微信不允许直接唤起 QQ），此时"复制群号"是唯一可用路径 —— 所以它必须始终可见，不能藏在折叠里
- 二维码用 `<img>` 而非 CSS 背景，否则微信/QQ 的「长按识别」不生效
- 🟡 需要真实 QQ 群号

桌面端保持原设计（二维码为主 + 取景框 hover 细节）。

### 6.4 `/tracks/[slug]` 路线图

桌面是横向、终点分岔。移动端改纵向：

```
  ● 大一 · 打基础
  │   · Python 语法与工程规范
  │   · 数学基础补足
  │   · 复现一个经典模型
  ●  大二 · 攻技术
  │   · …
  ┴─┬─┐               ← 大三分流点
    │ │
    ● ●
  就业 考研
```

绘制方向从"从左到右"改为"从上到下"，与滚动方向一致——这反而比桌面版更自然。大三的两条支线在竖屏下左右并排，**等宽等权**，不做上下堆叠（上下堆叠会读成"先就业再考研"的顺序关系）。

### 6.5 `/works/[slug]` 作品详情

- ② 对照滑块：全宽 16:9，手柄触控区 ≥44px 宽（视觉上可以是 2px 细线，用透明 padding 撑够）
- ④ 分层技术栈：桌面多列 → 移动端单列，每层一个标题 + 换行标签流
- ⑤ 质量证据：桌面表格 → 移动端堆叠条目（同 §6.2）
- ⑥ 边界：正常段落，不折叠。**不要因为"负面内容"就把它藏进折叠面板**——那等于承认它见不得人
- ⑧ 前后导航：上下堆叠两个满宽块，不并排

### 6.6 导航

- Header 高 56px（滚动后 48px）
- 汉堡按钮 44×44px，位于右上角
- 展开为**全屏面板**（`100dvh`），不是下拉菜单——下拉菜单在长导航时会超出屏幕
- 面板内：4 个导航项（≥56px 行高）+ 主题切换 + 「加入」满宽 CTA
- 入场：面板整体从右滑入 220ms + 4 个导航项 40ms 步进交错
- 打开时 `<body>` 加 `overflow: hidden` 且用 `inert` 屏蔽背景，焦点陷阱由 Radix Dialog 提供
- 关闭：点击遮罩、按 `Esc`、点击任一导航项

## 7. 触控与手势

| 规则 | 值 |
| :--- | :--- |
| 最小触控目标 | **44×44px**（WCAG 2.5.5 AAA）。视觉尺寸可以更小，用透明 padding 撑够 |
| 相邻触控目标间距 | ≥8px |
| 按下反馈 | `:active` 时 `scale(0.98)` 或背景变化，**80ms**。触屏没有 hover 预告，按下反馈是唯一的"我收到了"信号 |
| 点击高亮 | `-webkit-tap-highlight-color: transparent`，但**必须**用 `:active` 自己实现反馈，否则会变成"点了没反应" |
| 横向滑动 | **默认不使用**。不做轮播、不做左右滑卡片——它们与浏览器的返回手势冲突。**唯一例外**：`/works/[slug]` 的明暗截图对照滑块，因为它有可见手柄、是用户主动控制的、且设了 `touch-action: pan-y` 保证纵向滚动不受影响。同时必须提供键盘等价（`←`/`→`） |
| 长按 | 仅二维码（系统识别行为），不自定义长按交互 |
| 双击缩放 | 不禁用。禁用缩放是可访问性倒退（WCAG 1.4.4） |

```css
button, a, [role="button"] {
  -webkit-tap-highlight-color: transparent;
  touch-action: manipulation;   /* 消除 300ms 点击延迟，但保留缩放 */
}
```

## 8. 表单

`/join` 的报名表是全站转化终点，移动端体验直接决定成败。

| 字段 | `type` / `inputmode` | `autocomplete` |
| :--- | :--- | :--- |
| 姓名 | `text` | `name` |
| 年级与专业 | `text` | `off` |
| 联系方式（QQ/手机） | `text` + `inputmode="numeric"` | `tel` |
| 意向方向 | 原生 `<select>` | `off` |
| 一句话 | `<textarea rows="4">` | `off` |

**关键细节**：

- **输入框 `font-size` 必须 ≥16px**。iOS Safari 在字号 <16px 时会自动缩放页面，且不会缩回去——这是移动端表单最经典的坑
- 意向方向用**原生 `<select>`**，不用自定义下拉。原生控件调起系统选择器，在移动端体验远好于任何自绘方案
- 提交按钮**满宽**，高 48px
- 键盘弹出时不使用 `position: fixed` 的元素（安卓内置浏览器下会错位）。提交按钮跟随文档流
- 校验失败时 `element.scrollIntoView({ block: 'center' })` 把首个错误滚到可见区中央——键盘占了半屏，错误信息很容易被挡住
- Turnstile 组件宽度自适应，不溢出

## 9. 微信 / QQ 内置浏览器

**必须实机验证的环境。** 已知约束：

| 项 | 情况 | 应对 |
| :--- | :--- | :--- |
| iOS 内核 | WKWebView（Safari 引擎），跟随系统 Safari 版本 | 老 iOS 上 View Transitions / CSS 滚动时间线可能缺失 → 已按渐进增强设计 |
| 安卓内核 | 微信 XWeb（Chromium 系），版本滞后于最新 Chrome | 同上 |
| 地址栏行为 | 顶部有标题栏，会遮挡 | 用 `100svh`，不用 `100vh` |
| 外链跳转 | 点击站外链接会顶部弹出警告条，视口高度变化 | 不要有依赖精确视口高度的布局 |
| 唤起 QQ | 微信内**禁止**唤起 QQ 深链 | 必须提供"复制群号"兜底，见 §6.3 |
| 分享卡片 | 自定义标题/缩略图需要微信 JS-SDK + 已认证公众号绑定域名 | 🟡 社团若无公众号，只能依赖页面 `<title>` 与页面首图。文档如实标注，不承诺做不到的事 |
| 长按识别二维码 | 需要二维码是 `<img>` 元素 | 二维码用 `<img src="/images/qr/qr-group.svg">`，不用 CSS 背景 |
| 字体 | 系统中文字体可用，与常规浏览器一致 | 无影响（本项目正文中文本就走系统栈） |
| 缓存 | 内置浏览器缓存策略较激进 | 静态资源用内容哈希文件名（Next.js 默认行为） |

## 10. 移动端性能

移动端预算比桌面更严，因为设备更弱、网络更差。

| 指标 | 移动端目标 |
| :--- | :--- |
| LCP（4G） | < 2.0s |
| INP | < 150ms |
| CLS | < 0.02 |
| 首屏 JS（gzip） | < 120KB |
| Hero 首图 | AVIF，< 80KB |
| Lighthouse 移动端性能 | ≥ 92 |

**手段**：

- 图片 `sizes` 必须正确声明，避免手机下载桌面尺寸的图（`next/image` 的 `sizes="(max-width: 640px) 100vw, 50vw"`）
- 记忆点动效在移动端时长缩短 20–30%
- 移动端不加载桌面专属组件（航迹轨的桌面版通过 CSS 隐藏还不够，条件渲染更好）
- `SpotlightCard` 的 `pointermove` 监听在 `@media (hover: none)` 下**根本不注册**，不是注册了不用
- 中文正文零字体下载（系统栈）——这条对移动端收益最大

**实机测试基线**：一台中端安卓（约骁龙 6 系，2 年前机型）+ 一台 iPhone SE/13。不能只看 Lighthouse 模拟。

## 11. 移动端测试矩阵

上线前必须实机走完：

| 设备 | 浏览器 | 必测内容 |
| :--- | :--- | :--- |
| iPhone（iOS 17+） | Safari | 全站六路由 × 明暗主题；`100svh` 无跳动；表单不触发缩放 |
| iPhone | **微信内置** | 扫码进入 → 首屏 → `/join` 提交全流程；复制群号 |
| iPhone | **QQ 内置** | 同上 + 深链唤起 QQ |
